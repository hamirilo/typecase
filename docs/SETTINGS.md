# 設定画面とライブラリごとの設定

アップデートの確認・起動時の動き・サイドバーの項目など、あちこちに散りがちな設定を 1 つの設定画面にまとめる。
サイドバーの固定項目（お気に入り・ピン留めなど）は、使わない人もいるので隠せるようにする。

## 決定

| 論点 | 決定 |
|---|---|
| サイドバーで隠した項目 | **表示だけ隠す**。B キーやお気に入りへの追加などの操作はそのまま使える |
| サイドバーの設定の単位 | アプリ全体の既定と、ライブラリだけの設定。ライブラリごとに「アプリ全体の設定を使う／このライブラリだけの設定」を選ぶ |
| ライブラリごとの設定の保存先 | **`library.db`**。ライブラリのフォルダごと持ち運べば設定も付いてくる |

## 設定の置き場所（3 層）

| 層 | 保存先 | 中身 |
|---|---|---|
| アプリ全体 | `settings.json`（`app_config_dir`、`commands.rs` の `AppSettings`） | 起動時に開くもの、アップデートの自動確認、サイドバーの既定、ライブラリ一覧 |
| ライブラリごと | `<name>.library/library.db` の `settings` テーブル | サイドバーで隠す項目、サイドバーをアプリ全体に従わせるか、自分の見本のパターン |
| 表示の好み | `localStorage` | レイアウト・グループ分け、サムネイルの大きさ、パネルの開閉、比較ビューの設定など |

表示の好みはライブラリに付けない（どのライブラリでも同じ見た目のほうが迷わない）。
ライブラリに付けたくなったものだけ、あとから `settings` テーブルへ移す。

クラウドの同期フォルダなどに置いたライブラリを、複数の PC で（1 台ずつ）使う場合、ライブラリごとの設定はどの PC でも効く。
同時に開くことは想定しない（`library.lock` で確認を出す。docs/FEATURES.md の「バックアップ」）。

## ライブラリごとの設定

### データ

```sql
CREATE TABLE settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL  -- JSON
);
```

| key | value | 無いとき |
|---|---|---|
| `hidden` | サイドバーで隠す項目 `["pinned","untagged"]` | 何も隠さない |
| `sidebar` | `"own"` = このライブラリだけの設定、`"app"` = アプリ全体の設定を使う | アプリ全体の設定を使う |
| `specimenPatterns` | 自分の見本のパターン（新しい順） | 無し |

- 読み書きは `get_library_settings` / `set_library_setting`（`null` で消す）。フロントは `src/lib/librarySettings.ts` で読む
- 知らないキーや、知らない項目の ID は読み飛ばす（古い版で開いても壊れない）

### サイドバーの項目

| ID | 項目 | 隠せるか | 備考 |
|---|---|---|---|
| `all` | すべてのフォント | × | 開いたときの表示先 |
| `unfiled` | 未分類 | ○ | |
| `untagged` | タグなし | ○ | |
| `system` | この端末のフォント | ○ | |
| `favorites` | お気に入り | ○ | |
| `pinned` | ピン留め | ○ | |
| `trash` | ゴミ箱 | × | 削除したものの行き先が見えなくなるため |
| `section:folders` | フォルダ（節ごと） | ○ | |
| `section:smart` | スマートフォルダ（節ごと） | ○ | |
| `section:tags` | タグ（節ごと） | ○ | |

一覧は `SIDEBAR_ENTRIES`（`librarySettings.ts`）。シェルフはサイドバーではなく詳細パネルのタブ（docs/FONT_UI.md）。

**隠し方・戻し方**

- 項目または節の見出しを右クリック →「サイドバーから隠す」。書き込むのは **いま効いている側**（アプリ全体に従うライブラリなら全体）。
  トーストで「すべてのライブラリで隠しました」「このライブラリで隠しました」と効いた範囲を出し、［元に戻す］を付ける
- 設定画面の「サイドバー」（アプリ全体、またはライブラリ）にチェックリストを置き、そこで戻す（隠すのもここでできる）
- 隠していることはサイドバーには出さない。戻すのは設定画面から

**隠した項目の振る舞い（表示だけ隠す）**

- 機能はそのまま：お気に入りやピン留めの切り替え、件数の集計（`get_counts`）は今までどおり
- いま開いている表示を隠したら「すべてのフォント」へ移る
- 隠した表示へ追加したときは、トーストに［お気に入りを開く］などを付けて、その表示へ行けるようにする
- 「フォルダ」の節を隠しても、フォルダ選び（Shift+D、`FolderPicker`）は使える

**アプリ全体とライブラリ**

- 「このライブラリだけの設定」に切り替えたとき、ライブラリの `hidden` が空ならその時点の全体の値を写して編集を始める
- 全体に戻してもライブラリの `hidden` は消さない（また個別にすると前の値に戻る）
- フロントエンドは起動時に `settings.json` を読んで `store.appSettings` に持つ。いま効いている側は `sidebarScope`、その非表示は `sidebarHidden`（`store.ts`）
- 全体設定は PC ごと。全体に従うライブラリは PC によって見た目が変わる。持ち運ぶ前提のライブラリは「このライブラリだけの設定」にする

## 設定画面

```
設定
 アプリ全体
   一般              起動したとき・アップデート
   サイドバー         全体の既定
 ─────────
 ライブラリ「名前」     見出しの下に小さく「このライブラリに保存」
   概要              名前・場所・件数・容量、別のライブラリへ移す
   サイドバー         ◉ アプリ全体の設定を使う ○ このライブラリだけの設定
```

- ⌘, で開くモーダル。入口はライブラリメニューの「設定…」と、macOS のアプリメニューの「設定…」
- 左にページの一覧、右に中身。変更はその場で保存する（「保存」ボタンは置かない）
- ライブラリを開いていないときは「ライブラリ」の見出しごと出さない
- ライブラリのサイドバー：全体に従うときはチェックの一覧を全体の値で薄く出し（触れない）、「アプリ全体の設定を開く」を添える
- `SettingsTab` は `general` / `sidebar` / `library` / `librarySidebar`

### 枠と行（どのツールでも同じ）

枠・行・スイッチは `components/SettingsFrame.tsx`、「アップデート」の節は `components/UpdateSection.tsx`。
workbench の各ツールにも同じファイルを置いている（desktop-platform UI §9）。

- 右側の上に開いているページの名前と閉じるボタン。ページの中は「見出し＋枠で囲んだ行」の節を並べる
- 行は左に名前と説明、右に操作。オン／オフはスイッチ（行のどこを押しても切り替わる）、少しの中から 1 つ選ぶものはラジオの行、
  一覧から選ぶもの（サイドバーの項目）はチェックボックス
- ⌘, は最後に見ていたページで開く（ライブラリのページで、ライブラリを開いていなければ「一般」）。↑↓ でページを移る。
  Tab はダイアログの中だけを回り、閉じるとフォーカスは開く前の場所に戻る

### 一般（アプリ全体）

- 起動時：前回のライブラリを開く／ライブラリを選ぶ（`settings.json` に `startup: "last" | "choose"`）
- 「アップデート」の節（`UpdateSection`）：
  - アプリのアイコン・名前・バージョンと、確認の結果（確認しています… / 最新版です / v0.2.0 が使えます / 確認できませんでした）。
    ボタンは「アップデートを確認」、新しい版があるときは「更新内容」と「更新して再起動」
  - アップデートを自動で確認する（`autoUpdate: bool`、初期値オン）。オフなら `scheduleUpdateCheck` を動かさない
  - このバージョンの更新内容（GitHub のリリースのページ）
- このページを開いているあいだの確認は、結果をこの節に出す（トーストもダイアログも出さない）
- Windows のヘルプメニューの「Typecase について」はこのページを開く

### 概要（ライブラリ）

ライブラリの名前と場所（「Finder で表示」）、件数と容量。「別のライブラリへ移す」の節に、すべてのフォント（ゴミ箱のものを除く）を
別のライブラリへコピー・移動する入口を置く。

### アップデートの知らせ方

`lib/update.ts`。desktop-platform Distribution §4 に合わせている。

- 新しい版が見つかったら OS のダイアログで聞く。タイトルにアプリ名を入れる（macOS では太字の 1 行目、Windows ではウィンドウのタイトル）：

  ```
  Typecase の新しいバージョンがあります
  v0.2.0 が使えます（今のバージョンは v0.1.0）。
  更新すると Typecase が再起動します。
                       [更新内容を見る] [あとで] [更新して再起動]   ← macOS の並び
  [更新して再起動] [更新内容を見る] [あとで]                       ← Windows の並び
  ```
- 更新内容（リリースノート）はダイアログに載せない。「更新内容を見る」で GitHub のリリースのページ
  （`https://github.com/hamirilo/typecase/releases/tag/v<version>`、Rust の `open_release_page`）を開く。
  リポジトリは updater の `endpoints` の 1 つ目から決める（`--config` で配信先を変えたビルドでは、そのリポジトリのページ）。
  ダイアログは閉じ、「あとで」と同じく設定の「アップデート」からいつでも更新できる
- 更新して起動し直した最初の 1 回だけ「Typecase を v0.2.0 に更新しました［更新内容を見る］」のトーストを出す
  （前回のバージョンは `localStorage` の `lastVersion`）

### ライブラリメニュー（サイドバー下部）

ライブラリの一覧・「ほかのライブラリを開く…」「新しいライブラリを作成…」と「設定…」だけにする（メニューバーの「ファイル」にも置く。MENUS.md）。

### サイドバーの固定項目

```
すべてのフォント / 未分類 / タグなし / この端末のフォント
──
お気に入り / ピン留め
［ゴミ箱］                    ← 枠で囲む（docs/NAVIGATION.md）
フォルダ / スマートフォルダ / タグ の節
```

- 区切りは細い線だけで見出しは付けない
- 隠した項目で 1 つのまとまりが空になったら、その区切り線も出さない

## 後で足す候補（今回は作らない）

- ゴミ箱の自動削除（n 日たったら完全に削除）：ライブラリごと
- フォント見本の既定の文字と大きさ：今は `localStorage`。ライブラリごとに変えたくなったら移す（自分のパターンはもうライブラリごと、`specimenPatterns`）
- 取り込みの既定（取り込み時に付けるタグ、保存先フォルダ）：ライブラリごと
- 外観（ライト／ダーク）：OS に従う（docs/UI.md「色」）。アプリ側で選べるようにするのは、ウインドウのテーマを変える権限（capabilities）が要るので人の判断。今は作らない
